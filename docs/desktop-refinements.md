# 桌面体验与 PPT 模式

[English](desktop-refinements.en.md)

## 入口与模式

新 Windows 本地配置默认使用增强模式：左上角只保留侧栏开关和“应用”，LETS 品牌不变。不再显示“编辑”按钮，输入区原有复制、粘贴、撤销等快捷键不变。“应用”一级菜单固定为“视图”“工具”“检查更新”“关于 LETS”“退出应用”；重新加载和开发者工具归入“视图”，终端、远程控制、重启、恢复模式和导出诊断归入“工具”。不支持远程控制时不显示该工具。退出应用不等同于退出账号，企业应用仍在侧栏打开。

企业模式在左下角设置同一行的右侧显示当前员工姓名，点击打开原生账号菜单，查看姓名、登录账号和部门，或切换账号、退出登录。长姓名省略显示并可通过悬停查看；侧栏收起时保留有姓名提示的用户图标，支持键盘操作。姓名来自当前企业身份，不使用 Windows 用户名。页面只接收姓名、账号、部门三个公开展示字段，凭证仍在主进程；菜单仅允许当前受信任主页面调用。账号切换继续有序停止旧 Host 后重启回登录页，不复用旧工作区实例。

设置中仍可切换模式；已有 Profile 的明确选择不会被强制覆盖。旧浏览器／局域网访问设置继续使用兼容模式，安全模式也保留兼容布局。普通开发模式不显示企业账号入口。

旧账号如果仍显示扩展模式，请在“设置 → 桌面”选择增强模式并确认重启，无需新建 Profile 或迁移数据。

Windows 桌面的侧栏和输入区“添加工作区”直接调用一次系统文件夹选择器。取消不会新增工作区；系统选择失败或卷校验失败由原工作区错误页提示重试。普通浏览器继续使用自己的目录浏览流程。工作区的原生卷校验和服务端创建校验均保留。

## 插件管理

增强和扩展模式的“插件”页面使用桌面端自己的 Profile 管理接口，区分用户插件、内置／受保护插件包和当前进程的运行时组件。运行时状态与下次启动配置分开展示，支持搜索、刷新和错误重试。兼容模式不替换上游页面；企业网页应用仍在“企业应用”入口。

用户插件的启停需二次确认，只写入当前账号、当前 Profile 的启动状态，保留插件文件和历史数据。停用记录在三种市场选择下统一生效；切换市场不会重新启用已停用的用户插件。核心 Web 包、桌面入口、PPT 和具有专用设置的市场／远程控制组件不开放此页启停。修改不会在当前 Host 热卸载代码，需先保存工作，再显式重启桌面生效。

添加入口目前仅支持可信第三方 npm 插件的精确版本，如 `example-dsh-plugin@1.2.3`；不支持版本范围、任意命令、Git／URL／本地路径或覆盖已有依赖、内置包。填写后仍需确认“第三方代码可在本机执行”的风险。安装复用桌面端原有、限定当前账号 Profile 的 CLI 与受控 pnpm 子进程；配置备份保留在该 Profile 的 `.desktop-plugin-backups/`。失败不自动回滚其他进程的修改、不自动删除文件、不自动重启；缺少 DSH bundle 声明的普通 npm 包不会被当作可用插件。备份不是整份依赖树的事务快照。

管理 API 复用 Connection 认证，另校验实际回环连接与同源请求，写操作必须携带 Origin。确认令牌绑定当前 Host 生命周期、一次性使用并在五分钟后过期。账号切换会取消并等待当前安装进程退出；页面不接收账号路径、原始安装日志或凭证。此页不提供卸载功能，也不引入企业插件审批／分发平台。

## 品牌蓝资源页面

插件、技能与 MCP、企业应用采用桌面自有的统一品牌蓝界面：浅蓝灰底、白色资源卡片、蓝色主操作，以及有文字说明的状态颜色。跟随现有深色主题，支持窄窗口、键盘焦点和减少动态效果设置，不修改侧栏、聊天界面或上游子模块。

插件页默认收起内置插件和运行时组件，优先展示用户扩展；技能与 MCP 保留企业资源和我的安装两个入口，个人 Skill 仅导入 ZIP，也可拖入选择。企业应用支持名称／用途搜索和分类筛选，仍在隔离的桌面内嵌网页中打开。手动刷新有反馈，资源定时核验保持静默，不重置筛选或关闭弹窗。以上均不改变授权、风险确认、账号隔离和不删除文件的规则。

## PPT 使用

先选择工作区，在新会话中开启输入框上方的 PPT 按钮，选择模板，然后描述内容需求。可先预览模板，再选择或取消。内置 16 套模板、每套 12 个版式，包含中英文源示例；英文缩略图不限制生成语言。输出经过 PPTD 校验后导出可编辑 PPTX，校验错误需要修正，不能把失败当作成功交付。

PPT 模式和模板按会话持久化，关闭模式后普通聊天不再自动注入 PPT 指令。个人模板属于当前账号的本地 Profile，不是企业共享模板库；导入复杂公司模板后仍应核对版式、字体和 Office 对象保真度。

PPT 数据位于当前账号 Harness home 下的 `ppt/`，不会迁入其他账号数据；文件写入与导出仍限于当前工作区。未登录不能绕过企业启动校验。模型调用继续走企业模型网关，不在 PPT 插件另存供应商密钥。

## 工程与开发

`dsh-ppt-runtime/` 是根 Yarn 管理的私有 `dsh-ppt` 工作区，独立于未修改的 `deepseek-harness/` 子模块。来源固定为 dataelement/dsh-desktop 的 `bc732f5dc4c5465915d5b3f28d9b0b32703fc664`，原始来源、许可证和模板改编说明保留在 `PROVENANCE.md` 及 `packages/ppt-runtime/`。维护的 JS 种子不是重新声称拥有的完整原版 TypeScript 源码。

两版使用各自版本限定的已发布会话包补丁，补充三个 PPT 扩展插槽，不升级 Harness 家族、不编辑子模块。安全模式不装载 PPT。增强模式中的布局消费者只在子插件等待布局，不能让提供布局的桌面父插件等待自身服务。

正常安装：在根目录用 `corepack yarn install --immutable`，然后 `corepack yarn workspace dsh-ppt build`。模板、预览和临时文件仅写入新 PPT 模块的 `.build/ppt-runtime/`；不清理旧桌面 `lib`、账号目录或历史产物。企业增量启动命令会先检查并构建 PPT；输入未变时复用构建结果。

本机在禁止重建既有依赖树的约束下，另用 `.enterprise-local/ppt-dependencies-20261017/` 安装新增依赖，再通过 `scripts/link-ppt-development.mjs` 仅添加缺失链接。该目录不是另一套产品包管理器；仍使用同一 Yarn 4.18。根锁文件通过 `install --mode=update-lockfile` 更新，跳过原依赖树链接。全新环境直接正常根安装即可，不依赖这个本机目录。

回归：根目录 `corepack yarn test:ppt` 构建并验证两版 Harness 的模板、真实可编辑中文 PPTX、会话启停、工作区路径限制和 Windows 临时锁重试；已纳入根测试和完整检查入口。也可运行 `node --test dsh-ppt-runtime/test/*.test.mjs`，用 `DSH_PPT_TEST_EDITION=dsh-plugin-desktop` 切换稳定版。测试产物留在新 `.build/acceptance/`，不自动删除。窗口菜单、文件夹选择和模板预览仍需 Electron 实机验证。网页预览不代替原生验收。
